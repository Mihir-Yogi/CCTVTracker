7. ROLE RESPONSIBILITIES

SUPER ADMIN

Global system administrator.

Can:

* Manage organizations
* Create/manage Admin accounts
* View all organizations
* Manage system-wide settings
* Manage users
* View audit logs
* View system-wide reports
* Access all infrastructure data

Super Admin is NOT restricted to one organization.

⸻

ADMIN

Organization-level administrator.

Can manage the organization assigned to them:

* Locations
* Sub-locations
* NVRs
* DVRs
* HDDs
* Combos
* CCTV cameras
* Operators
* Operational records
* Replacements
* Reports

Admin must NOT access another organization’s data.

⸻

OPERATOR

Operational user.

Can:

* Login
* View permitted infrastructure
* View locations
* View sub-locations
* View assigned/authorized combos
* View cameras
* Perform daily status transactions
* Mark status
* Select predefined failure reasons
* Add remarks
* Record recovery/fix status
* View permitted operational history

Operator must NOT:

* Create Admin users
* Create Super Admin users
* Change their own role
* Modify organization ownership
* Delete system-critical records
* Access unauthorized organizations
* Modify security settings

16. BACKEND AUTHORIZATION

Every protected API/action must verify:

1. Is the user authenticated?
2. What role does the user have?
3. What organization does the user belong to?
4. Does the user have permission for this operation?
5. Does the requested resource belong to the user’s organization?

Example:

Admin A
Organization A
tries to access:
Camera belonging to Organization B

The backend must reject the request.

Do not rely on:

?organizationId=...

from the frontend as proof of authorization.

Authorization must be determined server-side.
