12. SECURE REGISTRATION RULE

This is extremely important.

Do NOT create a public registration form that allows anyone to choose:

Super Admin
Admin
Operator

That would be a security vulnerability.

Instead:

Super Admin

Created through a secure initial/bootstrap setup or controlled deployment process.

Admin

Created/invited by Super Admin.

Operator

Created/invited by an authorized Admin.

The registration/invitation UI may exist, but the user must not be able to escalate their own role.

Example:

Super Admin
     ↓
Creates Admin
     ↓
Admin receives account/invitation
     ↓
Admin logs in
     ↓
Admin creates Operator

Role assignment must always be enforced server-side.
